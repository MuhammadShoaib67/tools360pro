How to make a QR code for your website

By Muhammad Shoaib · Published 23 November 2026 · Updated 23 November 2026

A QR code turns a printed surface into a doorway: someone points a phone at your business card, poster or shop window and lands straight on your website, with nothing to type. Making one takes under a minute, costs nothing and needs no account — but the details decide whether people actually scan it. Here is how to make a QR code for your website, which address to put inside it, and the print mistakes that leave codes unscanned.

What a website QR code actually is

A QR code is just your website address written as a pattern of black and white squares. When a phone camera reads the pattern, it decodes the address and offers to open it in the browser. Nothing about the code itself is clever — the clever part is removing the typing. A long address that nobody would ever type from a poster becomes one camera tap, which is why QR codes work so well on anything printed: cards, flyers, menus, packaging, receipts and shop windows.

The codes made with our QR Code Generator are static, which means the address is encoded directly into the pattern. There is no redirect service sitting in between, no tracking, and no account — and that is exactly why the code never expires. It keeps working for as long as the address itself works. The trade-off is honest and worth knowing before you print a thousand copies: a static code cannot be edited later. If you change the address, you need a new code. So get the address right first, then print.

Make the code in four steps

Open the QR Code Generator and follow these steps — the whole thing takes less than a minute.

1. Paste your website address. Type or paste the full address into the text box, starting with https:// — for example https://example.com. The code updates live as you type, so you can watch the pattern appear in the preview.

2. Choose a download size. The size selector offers 256, 512 and 1024 pixels. For screens and documents, 512 is plenty. For print, pick 1024 if you are downloading a PNG — or download the SVG instead, which stays perfectly sharp at any size and is the better choice for anything printed.

3. Adjust the colours if you like. Black squares on a white background scan most reliably, and a brand colour for the squares works well as long as the contrast stays strong. Keep the background light and the squares dark; light squares on a dark background, or two similar colours, can defeat a phone camera in poor light.

4. Test it, then download. Before you download anything, scan the preview with your phone camera and confirm it opens the right page. That five-second test catches a mistyped address before it becomes a hundred misprinted posters. Then download the PNG for everyday use or the SVG for print.

Which address to put inside the code

The most common mistake is pointing every code at the homepage out of habit. The right address is the page the scanner actually wants. A business card or a shop window should point at the homepage, because the scanner is meeting your business for the first time. But a poster advertising one product should point straight at that product's page, a menu code should open the menu, and a flyer for an event should open the booking page. Every extra tap between the scan and the thing they wanted loses people — sometimes most of them.

Keep the address short. A short address makes a cleaner code: fewer characters mean a less dense pattern, and a less dense pattern scans faster and from further away. If your address is long, shorten it first, and strip out tracking parameters before you paste it in — a string of utm_ parameters adds density for no benefit to the person scanning. And always use the https:// version of the address, exactly as your site serves it, so the browser opens it without a redirect or a security warning. Our guide on how to make a QR code for a link, a PDF or a Google Form works through the same choice for those three cases, with the same rule: the code should open what the scanner came for.

Where to put the code — and how big it must be

A QR code only works if someone can scan it comfortably, and that is a question of size and distance. The further away the scanner stands, the larger the code must be. A code on a business card is scanned from a few centimetres away, so it can be small — around 2 cm across is enough. A code on a poster across a room needs to be much larger, and a code on a shop window that people read from the pavement needs to be larger still. A rough rule that holds up in practice: the code should be at least one tenth of the distance people will scan it from. If they stand a metre away, make it at least 10 cm across.

Good places for a website code are the ones where the person is already looking at your business: business cards, the back of a receipt, product packaging, a menu, a flyer, a poster, a shop window, and the footer of a printed invoice. Less good are places where nobody pauses — a passing vehicle, a tiny corner of a crowded poster — because a code nobody has time to scan is decoration, not a doorway. Wherever you put it, add a short line next to it saying what it opens: "Scan to visit our website" tells people why they should bother, and it costs nothing.

The print mistakes that make codes unreadable

Most unscannable codes fail on one of four things, and all four are easy to avoid. First, low contrast: light squares on a dark background, brand colours too close together, or a code printed over a photograph. Dark squares on a light background are the safe choice every time. Second, no quiet zone: cameras need a plain border around the code to find its edges, so leave breathing room and never crowd the code against other graphics or trim it tight.

Third, printing too small or at too low a resolution. A PNG stretched far beyond its pixel size turns fuzzy, and fuzzy squares do not scan — which is why SVG is the right download for print: it is sharp at any size. Fourth, and most expensive, never testing the printed copy. Paper, light and distance change what a camera sees, so scan the actual printed piece with a phone — not just the preview on your screen — before you print a large batch. One test scan of the finished print catches all four mistakes at once.

Static vs dynamic — which one is this?

Two kinds of QR code exist, and knowing which one you have avoids an unpleasant surprise. A static code, like the ones made here, holds the address directly. It never expires, costs nothing, needs no account, and cannot be changed after it is made. A dynamic code holds a short redirect link instead, so the destination can be changed later and scans can be counted — but it depends on a service that someone has to keep paying for, and if that service closes, every printed code stops working at once.

For a website address that is not going to change — a homepage, a shop, a portfolio — static is the right choice, and it is what this site makes. You lose nothing you need, and you gain a code that cannot be switched off by anyone. If your address does change one day, make a new code and reprint. For most small businesses that is a rare event, and a free, permanent code is a better deal than a subscription that can be taken away.
