How the conversion works

A JSON array of objects is already a table in disguise: each object is a row, and its keys are the columns. This tool reads the array, collects every key it finds into a header row, and writes one CSV row per object. Values that are numbers, booleans or strings go straight into their cells. A single object on its own is treated as a one-row table.

Headers are collected in the order they first appear, and every object contributes its keys — so if the third object has a key the first two lack, it still gets a column. Rows that do not have a value for a column get an empty cell. The result is a rectangular table, which is what spreadsheets expect.

CSV rules the output follows

CSV looks simple until a value contains a comma. This tool follows the standard quoting rules: any field containing a comma, a quote or a line break is wrapped in double quotes, and a quote inside a field is doubled. A product named Chair, wooden therefore arrives in one cell, not split across two — and a spreadsheet reading the file will put it back together correctly.

Nested objects and arrays cannot fit in a flat cell, so they are flattened to JSON strings inside their cells. A tags array becomes the text ["tech", "portable"] in one cell, and a nested details object becomes its JSON text. The data is preserved, but it is not expanded into extra columns — if you need one column per nested field, flatten the JSON first.

What to do with the CSV

The most common destination is a spreadsheet: open the downloaded file in Excel, Google Sheets or LibreOffice and the table appears, ready to sort, filter and chart. CSV is also the format data tools expect — databases import it, data-analysis tools read it, and colleagues who never touch JSON can work with it directly.

If the CSV opens in Excel with everything in one column, the cause is usually a regional setting: some locales expect a semicolon separator. Open the file through the import wizard and choose comma as the separator, and the columns will appear. The file itself is standard CSV either way.

A spreadsheet is also where small data-cleaning jobs become easy. Once the CSV is open, you can sort by any column, filter out rows you do not need, remove duplicates, and spot the empty cells where an object was missing a key. Do that tidying in the spreadsheet, not by editing the JSON — the table view makes problems visible in a way a wall of brackets never does.

Arrays to spreadsheets: headers, missing keys and nested values

A JSON array to CSV free conversion starts with the headers: they are the union of every key across all the objects, in the order each key first appears. An object missing a key gets an empty cell in that column, so every row has the same shape even when the objects differ. A single object works too — it becomes a one-row table.

Nested objects and arrays are not expanded into extra columns: they stay as JSON text inside their cell, so the data is preserved even though it is not flattened. Fields containing commas, quotes or line breaks are quoted, with quotes doubled, the way spreadsheets expect — so the downloaded CSV opens cleanly in Excel or Google Sheets.

Frequently asked questions

What if my objects have different keys?

Headers are the union of all keys across all objects, in the order they first appear. An object missing a key gets an empty cell in that column, so every row stays aligned.

What happens to nested objects and arrays?

They are flattened to JSON strings inside their cells, not expanded into columns. A tags array becomes its JSON text in one cell, preserving the data in readable form.

Can I convert a single object, not an array?

Yes. A single object is treated as a one-row table, with its keys as the header row and its values as the single data row.

Why are some fields wrapped in quotes?

Fields containing a comma, a quote or a line break must be quoted, or a spreadsheet would split them. Quotes inside a field are doubled, following the standard CSV rules.
