What schema markup is

Schema markup is structured data that tells a search engine what a page is about, in a format the engine can read directly. Instead of guessing from the visible text, the search engine reads a small block of JSON-LD code that says, in effect: this page is an article, written by this author, on this date. Or: this business is at this address and opens at these hours. The vocabulary comes from schema.org, a shared standard that Google, Bing and others all understand.

JSON-LD is the recommended format because it sits in a single script tag and does not change anything visible on the page. You paste the block into the page head or body, and visitors never see it, while search engines read it every time they crawl. This generator produces exactly that block: valid JSON-LD for the five most common types, with the field names and nesting that the standard requires.

Which type should you use

Article fits blog posts, news stories and guides: headline, author, date and publisher are the fields that matter. FAQPage fits a page that already shows questions and answers to visitors — the questions in the markup must match the questions on the page, or Google will ignore it. One honest note: Google now shows FAQ rich results mainly for government and health websites, so most sites should not expect the expanded FAQ display; the markup is still valid and still helps search engines understand the page.

LocalBusiness fits any business with a physical address: name, phone, address and opening hours are the core fields, and they feed the knowledge panel and map results. Product fits a product page and needs a name, price and currency at minimum; availability tells shoppers whether it can be bought. BreadcrumbList describes the trail of links at the top of a page (Home, Blog, Article), which Google may show in search results instead of the raw URL.

Test before you publish

Valid JSON is only the first check. Google also has its own rules about which fields each rich result needs, and those rules change, so the output of this tool should always be tested before it goes live. Paste the generated JSON into Google's Rich Results Test, or test the published page URL there: it reports errors, warnings and a preview of what the rich result would look like. The Schema.org validator is a second useful check for the markup itself.

Two habits keep schema useful rather than harmful. First, never mark up content that is not on the page: fake reviews, invisible FAQs and prices that do not match the page are the fastest way to lose rich results entirely. Second, keep the markup in step with the page — when a price changes or a question is removed, update the JSON-LD in the same edit, or the search engine will eventually notice the mismatch.

Frequently asked questions

Does schema markup improve rankings?

Not directly: schema is not a ranking factor. It can earn rich results such as star ratings, prices or breadcrumbs in search listings, and those often get more clicks, which is the real benefit.

Where do I put the JSON-LD?

Inside a script tag with type application/ld+json, in the head or the body of the page. Most CMS platforms and SEO plugins have a field for custom code where the block can be pasted.

Will Google show my FAQ as a rich result?

Probably not, unless the site is a government or health site: Google limited FAQ rich results to those in 2023. The FAQPage markup is still valid and still helps search engines understand the page.

Do I need a developer to add this?

Usually not. If your site runs on WordPress, Shopify or a similar platform, an SEO plugin or a custom code field accepts the script tag as-is. Static sites need one edit to the page template.

Is my data uploaded anywhere?

No. This tool runs entirely in your browser using JavaScript. Nothing you type is uploaded, stored or sent anywhere.

Which schema types can I generate?

Five: Article, FAQPage, LocalBusiness, Product and BreadcrumbList. Pick a type from the dropdown, fill in the fields, and the generator builds validated JSON-LD with a paste-ready script tag.

What is JSON-LD?

A way of writing structured data as a script tag on a web page, in a format search engines can read. JSON-LD describes what a page is — an article, a product, a local business — so search engines understand it without guessing from the visible text.

Do I need to update my schema when the page changes?

Yes — the schema should describe the page as it is now. If a product price, an opening time or an article date changes, regenerate the markup with the new details and replace the old script tag, so search engines are not reading stale data.
