How to use the Robots.txt Generator

  1. Leave the user-agent as * to address all crawlers, or type a specific one such as Googlebot.
  2. Add a rule for each path: Disallow to block a folder or page, Allow to make an exception inside a blocked folder.
  3. Add your sitemap URL if you have one, and a crawl-delay only if a crawler is hitting your server too hard.

What robots.txt actually does

A robots.txt file is a set of instructions for search engine crawlers. It lives at the root of a website, at example.com/robots.txt, and crawlers read it before they fetch anything else. The file says which parts of the site a crawler may visit and which parts it should leave alone, using simple rules: a user-agent line names the crawler, and Disallow and Allow lines name the paths.

The important thing to understand is that robots.txt is a request, not a lock. Major search engines honour it, and well-behaved crawlers do too, but nothing in the file physically stops anyone from opening a URL. A page blocked in robots.txt can still be visited by a person, linked from another site, and even indexed if Google finds enough links to it. For anything that must stay private, use a password or a noindex tag instead.

The rules, in plain language

User-agent: * addresses every crawler at once, which is what most small sites want. A specific agent such as Googlebot or Bingbot lets you write different rules for different crawlers. Disallow: /admin/ blocks everything under that folder, while Allow: /admin/public/ carves an exception back out of it. Rules are matched from the start of the path, so Disallow: /private blocks /private.html as well as /private/page.

Two optional lines round the file out. Sitemap: followed by your sitemap URL tells crawlers where to find the full list of your pages, which is useful even though you can also submit the sitemap in Search Console. Crawl-delay: 10 asks crawlers to wait ten seconds between requests, but be aware that Google ignores crawl-delay entirely; Bing and Yandex respect it. If Googlebot is overloading your server, the fix is in Search Console settings, not in this file.

Common mistakes to avoid

The most damaging mistake is a single wrong slash: Disallow: / blocks the entire site, and it has taken down more than one launch when a staging file was copied to production by accident. Always read the generated file once before uploading it, and check in Search Console that your important pages are still reachable. The second mistake is blocking CSS and JavaScript files: Google needs those to render a page, and blocking them can make a good page look broken to the crawler.

The third mistake is treating robots.txt as a privacy tool. A disallowed admin page, staging site or private document is still public if someone knows the address, and the robots.txt file itself advertises the paths you blocked, since anyone can read it. Keep sensitive content behind a login, and use a noindex meta tag on pages you want crawled but not shown in search results.

Frequently asked questions

Where does robots.txt go?

At the root of your domain, so it is reachable at example.com/robots.txt. A copy in a subfolder does nothing: crawlers only check the root.

Does robots.txt hide a page from Google?

No. It tells crawlers not to fetch the page, but Google may still index the URL if other pages link to it. To keep a page out of search results, use a noindex meta tag on the page itself.

What does Disallow: / do?

It blocks the whole site from the named crawler. It is useful on a staging site you never want indexed, and a disaster on a live site, so check the file before uploading.

Does Google follow crawl-delay?

No, Google ignores the crawl-delay directive. Bing and Yandex respect it. If Googlebot is crawling too aggressively, adjust the crawl rate in Google Search Console instead.

Is my data uploaded anywhere?
