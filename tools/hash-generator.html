Checksums: how downloads prove they are genuine

Every serious software download page shows a long string of hex characters next to the file — its SHA-256 hash. Feed the file you downloaded into a hash tool and compare: identical string, and the file is bit-for-bit the one the publisher released; a single changed byte anywhere produces a completely different hash. It is the simplest integrity check in computing, used for operating systems, installers, firmware and backups.

The four algorithms here cover the common cases: MD5 and SHA-1 still appear on older download pages (fine for spotting corruption, not for proving authenticity), while SHA-256 and SHA-512 are the modern standards. Everything runs in your browser using its built-in cryptography for the SHA family, so even a private file can be hashed safely — it never leaves your device.

Frequently asked questions

What is a hash used for?

A hash is a fingerprint of data. Websites publish the SHA-256 of a download so you can confirm the file you received is complete and untampered: if even one byte differs, the hash is completely different.

Is MD5 safe?

MD5 is fine as a quick checksum to spot accidental corruption, but it is no longer collision-resistant, so do not rely on it to prove a file is authentic or to store passwords. Prefer SHA-256 or SHA-512 for anything security-related.

Can a hash be reversed back to the original?

No. Hashing is one-way: the fingerprint cannot be turned back into the text or file. That is why hashes can be shared publicly when verifying downloads.

Is my file uploaded for hashing?

No. Your browser reads the file and computes the hashes on your device — handy for private or very large files that you would never send to a server.
